# Proposed Rules

Rules and conventions discovered during development that should be reviewed before adding to CLAUDE.md.

- **Rule:** Avoid incidental Genesis mentions in comments, doc headers, example values, or ticket refs when generic phrasing works. Intentional deployment resources (render.yaml services, docker creds, setup-doc URLs) that use the placeholder name are fine — just run `pnpm rename testname` against a clean tree and confirm the new reference shows up in the preview before committing. — **Context:** GENESIS-146. The rename script handles intentional deployment refs cleanly; it's the incidental ones (Genesis 2.0 headers, stale Notion IDs, Conrad-Labs-specific URL examples) that create pointless rename work for forking MVPs.
- **Rule:** Mobile navigation chrome is native-first: `NativeTabs` (`expo-router/unstable-native-tabs`) + native stack headers, with whole-screen `@expo/ui` (SwiftUI/Compose) deliberately deferred while alpha. Tiered adoption is documented in the "Native UI strategy" section of `apps/mobile/CLAUDE.md`. - **Context:** GENESIS-170 follow-up. Native feel was prioritized over brand styling for chrome; screen content keeps the Uniwind token-based design system shared with web.
- **Rule:** `apps/mobile` targets iOS and Android only; web is `apps/web`. Never add `react-native-web`, `.web.tsx` files, web fallbacks, or an `expo start --web` script to the mobile app. `react-dom` must STAY, pinned exactly equal to `react`: Clerk's transitive deps import it at runtime on native and React throws on any version skew (routes then fail with "missing the required default export"). `moduleSuffixes: [".ios", ".android", ""]` in its tsconfig lets `.ios`/`.android` pairs typecheck without a base file. - **Context:** Stated during GENESIS-170 native UI work; removing react-dom broke app startup with a react/react-dom 19.2.3 vs 19.2.5 mismatch.
- **Rule:** Mobile interactive controls (Button, Switch, future pickers/sliders) are native platform widgets via `@expo/ui` (SwiftUI / Jetpack Compose) behind the `src/components/ui/` barrel; Button is label-based (`label` prop, no `<Text>` children). Presentation components (Text, Card, Badge, Input) stay RN + Uniwind tokens. - **Context:** "Make all buttons, inputs, toggles native" request; Input stays RN `TextInput` because it already renders the native field and SwiftUI `TextField` is uncontrolled (breaks TanStack Form resets).
- **Rule:** Platform-specific mobile components use a **pair** of Expo platform extensions (`name.ios.tsx` + `name.android.tsx`) with **no** shared base file. When the component takes props, add a `name-types.ts` contract file that both platform files import their props type from. This guarantees both platforms are typed against one contract even though `moduleSuffixes: [".ios", ".android", ""]` means `tsc` only resolves imports to the `.ios` file. Prop-less pairs (example: `more-list.ios.tsx` / `more-list.android.tsx`) need no contract file. Never use `process.env.EXPO_OS` / `Platform.OS` branches inside shared files when platform files work. Hooks and utilities that have one genuinely cross-platform implementation may still use a base file + a `.ios` override (e.g. `use-native-header-options{,.ios}.ts`, `use-tab-tint-color{,.ios}.ts`), but components must always use the pair pattern. - **Context:** Codified during GENESIS-170 native UI work; `button-types.ts` and `switch-types.ts` are the canonical examples when props are present. Without the contract file when props exist, a props change in the Android platform file alone compiles green and only breaks at runtime on an Android device.
- **Rule:** In `apps/mobile`, never use `(await fetch(uri)).blob()` to read local files. Since SDK 56 the global `fetch` is `expo/fetch`, whose `blob()` constructs a Blob from an ArrayBuffer, which React Native's global `Blob` rejects at runtime on device ("Creating blobs from 'ArrayBuffer'... not supported"). Use `uriToBlob()` (`src/utils/uri-to-blob.ts`, XHR with `responseType: "blob"`), which yields an RN-native Blob that both oRPC's `instanceof Blob` check and expo/fetch's FormData converter handle. Likewise never wrap upload bytes in `new File(...)` on native: RN's `File.name` is a getter-only prototype accessor and Expo's FormData patch assigns `value.name`, throwing "Cannot assign to property 'name' which has only a getter". Use `toUploadFile()` (`src/utils/to-upload-file.ts`). - **Context:** iOS upload crashes on the storage screen; both failures only reproduce on device/simulator, not in tsc or web.
- **Rule:** ~~Superseded:~~ `apps/mobile` styling moved from NativeWind v5 preview to **Uniwind** (stable, Tailwind v4). The `lightningcss: 1.30.1` override in `pnpm-workspace.yaml` stays: `apps/web` (Tailwind v4 → lightningcss) still relies on it, and `uniwind` pins the same `lightningcss@1.30.1` internally, so the override keeps the tree consistent. Never bump it without re-verifying BOTH `expo export` (mobile) and `pnpm -F web build` (web). Mobile UI components are added via the react-native-reusables CLI (`npx @react-native-reusables/cli add <component>`), which auto-detects the uniwind registry from `withUniwindConfig` in metro config — see `apps/mobile/CLAUDE.md`. — **Context:** GENESIS-170. Originally documented the NativeWind v5 / react-native-css lightningcss deserialize failure; the Uniwind migration removed react-native-css from the tree, leaving the pin web-relevant only.
