- **Rule:** Avoid incidental Genesis mentions in comments, doc headers, example values, or ticket refs when generic phrasing works. Intentional deployment resources (render.yaml services, docker creds, setup-doc URLs) that use the placeholder name are fine — just run `pnpm rename testname` against a clean tree and confirm the new reference shows up in the preview before committing. — **Context:** GENESIS-146. The rename script handles intentional deployment refs cleanly; it's the incidental ones (Genesis 2.0 headers, stale Notion IDs, Conrad-Labs-specific URL examples) that create pointless rename work for forking MVPs.
- **Rule:** The `lightningcss: 1.30.1` override in `pnpm-workspace.yaml` is load-bearing for `apps/mobile`'s NativeWind v5 / Tailwind v4 styling — newer 1.31/1.32 produce CSS that `react-native-css` can't deserialize ("expected an object-like struct named Specifier"). It's a monorepo-wide override, so `apps/web` (also Tailwind v4 → lightningcss) shares the pin. Never bump it without re-verifying BOTH `expo export` (mobile) and `pnpm -F web build` (web). Also: on Expo SDK 56, use the latest `nativewind@5.0.0-preview.4` + `react-native-css@^3.0.7`, not the older pins in the `expo:expo-tailwind-setup` skill (those target SDK 54 and throw a Metro `addedFiles` error on 56). — **Context:** GENESIS-170. Wiring NativeWind into the Expo app: the deserialize failure was a lightningcss version skew, and the skill's pinned versions were a separate SDK-54-vs-56 Metro mismatch.
